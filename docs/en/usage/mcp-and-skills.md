# MCP and Skills

## Two Types of Extensions

- MCP Server provides Tools, Resources, and Prompts to the model.
- Skill injects reusable instructions, descriptions, and workflows into the assistant.

Both support global and project scope. Project configuration lives in the bound directory's `.aio/` and is reloaded when switching projects; downloading or installing does not mean it is already bound to the current assistant.

## MCP Server

AIO currently registers three transports:

| Transport       | Scope                               | Configuration                                           |
| --------------- | ----------------------------------- | ------------------------------------------------------- |
| stdio           | Local servers run via child process | Command, args, working directory, environment variables |
| HTTP            | HTTP + SSE style remote server      | URL, request headers                                    |
| Streamable HTTP | MCP Streamable HTTP Server          | URL, request headers                                    |

The settings page supports viewing, starting/stopping, testing, deleting, and editing servers. After connecting, capabilities are read and Tools, Resources, and Prompts are listed per server declaration; the chat only exposes tools that are bound to the current assistant or project and that are on the `enabledTools` allowlist. An empty allowlist means all tools are enabled.

A hidden `__aio-filesystem__` configuration is automatically written when creating a new project. The current implementation executes its tool names using built-in file tools, does not depend on external MCP sub-processes, but is still subject to project root and permission rule restrictions.

## stdio Configuration Example

The following structure shows non-sensitive fields in `mcp-servers.json`:

```json
[
  {
    "id": "demo-stdio",
    "displayName": "Demo stdio",
    "transport": {
      "transport": "stdio",
      "command": "npx",
      "args": ["-y", "@example/demo-mcp"],
      "env": {
        "DEMO_TOKEN": "${KEYRING:mcp-server-demo-stdio-env-DEMO_TOKEN}"
      },
      "cwd": null
    },
    "enabledTools": [],
    "autoStart": true,
    "hasStoredSecret": true
  }
]
```

On Windows, `.cmd` files corresponding to commands like `npx`, `npm`, `pnpm`, etc., are resolved. Processes are started via argument arrays, not concatenated shell strings.

`${KEYRING:...}` is generated by the settings page when saving secrets. Do not create placeholders manually, and do not write real tokens directly into `env`.

## HTTP Configuration Example

```json
[
  {
    "id": "demo-http",
    "displayName": "Demo HTTP",
    "transport": {
      "transport": "http",
      "url": "https://mcp.example.com/sse",
      "headers": {
        "Authorization": "Bearer ${KEYRING:mcp-server-demo-http-header-Authorization}"
      }
    },
    "enabledTools": ["search"],
    "autoStart": false,
    "hasStoredSecret": true
  }
]
```

Streamable HTTP uses the same URL and headers form and should be created through the Catalog or settings interface to avoid manually writing the wrong transport identifier. Remote addresses are checked for URL validity and SSRF.

## MCP Catalog

The Catalog page reads the official MCP Registry:

1. Checks the runtime required by the server (`npx`, `uvx`, etc.);
2. Selects available delivery methods among npm, PyPI, HTTP, or Streamable HTTP;
3. Collects required parameters and secrets;
4. Writes secrets to the system credential store and placeholders to the configuration;
5. Saves to the current global or project scope, with auto-start enabled by default.

Catalog results are cached in `mcp-registry-cache.json`. Before installing a third-party server, check the publisher, actual command, environment variables, and accessible scope.

## Tool Permissions and Approval

Permission decisions consider:

- Agent mode;
- Tool name and MCP Server ID;
- Paths in call arguments;
- Project `.aio/permissions.json` custom rules.

The result is `allow`, `ask`, or `deny`. Calls requiring confirmation generate an approval request; file modification tools can show a Diff before execution. Auto mode still asks for file deletions and is subject to the path sandbox, dangerous command checks, and explicit deny rules.

Example: Normal mode allows modifying `docs/**` but denies all delete tools:

```json
{
  "version": 1,
  "updatedAt": "2026-07-26T00:00:00",
  "rules": [
    {
      "id": "allow-doc-writes",
      "toolPattern": "write_file",
      "modes": ["normal"],
      "action": "allow",
      "pathPattern": "docs/*",
      "priority": 20
    },
    {
      "id": "deny-delete",
      "toolPattern": "delete_*",
      "modes": [],
      "action": "deny",
      "priority": 100
    }
  ]
}
```

Field reference:

| Field         | Behavior                                                                |
| ------------- | ----------------------------------------------------------------------- |
| `id`          | Unique rule identifier                                                  |
| `toolPattern` | Tool name, prefix/suffix `*` or `*`                                     |
| `serverId`    | Optional; only matches a specific MCP Server                            |
| `modes`       | Empty array matches all modes                                           |
| `action`      | `allow`, `ask`, or `deny`                                               |
| `pathPattern` | Optional; matches `path` in tool arguments                              |
| `priority`    | Higher number takes precedence; matched deny rules override allow rules |

Currently, glob only supports exact match and single `*` at the beginning or end; do not interpret it as full glob syntax. After modifying the permissions file, re-enter the project to reload the configuration.

> For the complete rule reference, including the three-tier model, evaluation order, and built-in default rules, see the [Permission System Reference](../reference/permissions.md).

## Resources and Prompts

A successfully connected server may expose:

- Resources: list URIs first, then read content on demand;
- Prompts: list templates first, then pass parameters to get messages.

Availability depends on the capabilities declared by the server. If a server does not declare the corresponding capability, AIO does not send unnecessary requests and the count in the status shows zero.

## Skill

"Settings -> Skill Management" provides:

- Skill marketplace;
- Downloaded global or project Skills;
- Skills discovered and imported from NPX packages.

The marketplace supports category, popular, and trending browsing, with a 6-hour cache. Project Skills are saved in `.aio/skills.json`, global Skills in the application data directory. After downloading or importing, they must also be enabled in the corresponding assistant or project settings before their content is injected into conversations.

## Project Files

```text
project/
└── .aio/
    ├── mcp-servers.json
    ├── permissions.json
    ├── skills.json
    └── knowledge.json
```

`knowledge.json` is only created after enabling cross-session memory and generating knowledge; `permissions.json` is only needed when custom rules exist. Before committing `.aio/`, check for environment-related paths and business information; secrets must remain as credential store placeholders.

For troubleshooting, see [MCP and Skill Troubleshooting](../troubleshooting.md#mcp-server-fails-to-start).
