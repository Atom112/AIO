# 故障排查

## Provider 无法连接

1. 在“设置 → 供应商设置”重新运行连接测试。
2. 检查 API URL 是否包含多余的 `/chat/completions`。
3. 确认 API Key 对目标模型有权限。
4. 确认服务的响应格式属于 Google、Anthropic、Ollama 或 OpenAI-compatible。
5. 自建服务若位于内网，检查 URL 是否被 SSRF 策略拒绝。

如果模型目录能显示但请求失败，目录元数据并不代表账号已开通该模型。

## Provider 代理无效

- 代理 URL 只作用于当前 Provider；它不会代理 MCP、更新检查或本地引擎。
- 使用完整的 HTTP/HTTPS URL，例如 `http://127.0.0.1:7890`。
- 确认代理进程正在监听对应地址，并允许 AIO 访问。
- 临时清空代理 URL 后重新测试，用于区分代理和 API 配置问题。
- 不要把密码直接写入 URL；当前字段不是凭据库入口。

目录刷新与对话请求走不同服务。前者成功不能证明 Provider 代理已经正确配置。

## 本地 llama.cpp 启动失败

- 确认选择的是可读取的 `.gguf` 文件。
- 首次启动需要联网下载引擎；检查防火墙和代理。
- 确认 `8080` 端口未被其他程序占用。
- 模型过大时降低模型规模或关闭其他占用内存/显存的程序。
- 移动模型文件后重新选择路径并添加模型。

引擎扫描与自动发现参见 [providers-and-models.md → 引擎扫描与自动发现](usage/providers-and-models.md#引擎扫描与自动发现)。vLLM 与其他本地引擎一样，通过引擎扫描自动注册，启动/停止操作在 Provider 详情页的引擎卡中统一管理。

## MCP Server 无法启动

1. 查看服务器状态和错误信息。
2. stdio Server：确认命令可在系统 PATH 中找到，参数和工作目录有效。
3. NPX Server：确认已安装 Node.js/npm，且网络可访问包源。
4. HTTP / Streamable HTTP Server：确认传输类型、URL、请求头和服务 capabilities。
5. 从 Catalog 安装时，先运行运行时检查并补齐必填密钥。
6. 项目 Server：确认当前选择了正确项目。

服务器连接成功但看不到工具时，检查项目/助手是否绑定该 Server，以及 `enabledTools` 白名单。

## MCP 工具一直等待确认

- 普通 Agent 模式会对敏感操作请求确认。
- 检查是否存在未处理的审批弹窗。
- 检查 `.aio/permissions.json` 是否把工具配置为 `ask` 或 `deny`。
- 自动模式不会覆盖明确拒绝规则和危险命令保护。

## Skill 没有生效

1. 确认 Skill 已下载或导入。
2. 确认当前范围是全局还是项目。
3. 在助手或项目设置中启用该 Skill。
4. 切换项目后等待 Skill 列表重新加载。
5. NPX Skill 更新失败时检查包管理器和网络。

## 附件无法上传

检查扩展名和大小：

- 图片最大 10 MiB；
- PDF、DOCX、PPTX 最大 30 MiB；
- 文本文件最大 5 MiB。

PDF 或 Office 文件能上传但无有效文本时，文件可能是扫描件、加密文件或包含当前解析器不支持的结构。

## Agent 无法访问项目文件

- 确认创建项目时选择的是目录而不是文件。
- 确认项目路径仍然存在。
- 检查当前助手是否属于该项目。
- Plan 模式不会修改文件。
- 文件工具和内置文件系统 MCP 都受项目根目录限制。
- 查看问题面板是否提示 LSP 未安装；LSP 失败不影响普通文件读取。

## 用量统计为空

用量数据在每轮 LLM 调用完成后自动写入 `usage_log` 表。以下情况可能导致统计为空或数据不全：

- 首次使用：新安装或刚刚开始使用 AIO，需要几轮对话后才会产生记录；
- 旧消息：早期版本的消息可能没有 Token 字段，不会被统计；
- 取消请求：被取消或 Provider 未返回用量的请求记录为零；
- 数据自动记录：`usage_log` 表在每次成功调用后写入，无需手动开启。

设置路径：设置中心 → 使用量。详细说明见[聊天与 Agent → 用量统计](usage/chat-and-agent.md#用量统计)。

## 快捷键不工作或发生冲突

- 输入框聚焦时，大多数全局快捷键不会触发；`Esc` 与发送相关按键例外。
- 在“设置 → 应用设置 → 快捷键设置”确认当前绑定。
- 同一组合被占用时，AIO 会要求确认覆盖；取消后旧绑定保持不变。
- 点击单项恢复按钮，或使用“恢复默认”清除全部自定义绑定。
- macOS 显示的符号与 Windows/Linux 文本不同，但绑定逻辑相同。

命令面板能看到操作但执行无反应时，先回到对应页面；部分处理器只在聊天页挂载时可用。

## 自动更新失败

- “当前 Release 未配置自动更新服务”表示对应版本缺少 `latest.json` 或签名产物，不是本地安装损坏。
- 网络错误时确认能访问 GitHub Releases，Provider 代理不会应用到更新请求。
- 只有正式签名的 Release 产物可以通过内置 updater 安装。
- 本地源码构建可正常运行，但不能代替正式更新包测试签名安装。

若下载完成但安装失败，保留当前版本，从 Releases 页面手动下载对应平台安装包。

## 系统自启设置失败

- 设置失败时开关会自动恢复，不代表已经注册成功。
- 确认当前用户有权创建用户级启动项。
- Linux 桌面环境可能使用不同的自启动目录或策略。
- macOS 或 Windows 的系统管理策略可能禁止应用自行注册。

系统自启只启动 AIO，不会直接绕过本地模型首次启动确认。

## 项目记忆没有生效

1. 在项目设置弹窗中确认已开启“项目记忆”（语义 RAG）。
2. 确认当前助手绑定了项目，而不是普通聊天助手。
3. 检查 `.aio/memory/memory.sqlite` 是否已产生，以及记忆面板是否有条目。
4. 让 Agent 明确记住一项事实，再在新话题中检索。

旧版 `.aio/knowledge.json` 会在首次打开记忆时自动迁移；迁移完成后旧文件仍保留，可自行删除。

## 子智能体等待或部分失败

- 批量委托允许 1–10 个子任务，实际默认最多并发运行 5 个，其余排队。
- 非自动模式下，检查是否有一条尚未处理的批量审批。
- 子智能体模型覆盖只列出云模型；本地模型通过继承主 Agent 使用。
- 某个子任务失败不会取消已经完成的其他结果，查看对应步骤卡片中的错误。
- 自定义角色若没有所需工具，应调整允许/拒绝列表或改用合适的内置角色。

## Diff 或撤销不可用

- Diff 只记录 AIO 文件工具捕获到的变更；外部编辑器的修改不会自动归入某轮回复。
- 完整撤销依赖项目是 Git 仓库且存在 `HEAD`。
- 撤销以 `git checkout HEAD -- <file>` 恢复文件，会同时丢弃该文件原有的未提交修改。
- 删除、移动或切换分支后，历史消息中的旧文件路径可能不再可恢复。

执行撤销前先用 `git status` 和 Diff 确认目标；重要改动应先提交或另行备份。

## 凭据保存失败

- 系统凭据库不可用时，AIO 会尝试使用加密的 `secure-store.json` 回退。
- 确认应用数据目录可写，且安全软件没有阻止凭据库访问。
- 不要把 `secure-store.json`、完整 Provider 配置或 MCP 配置上传到 Issue。
- 从其他设备复制配置后，应在设置页重新输入 API Key 和 MCP 密钥。

旧配置若含明文 `apiKey`，请轮换密钥并通过当前设置页重新保存。

## 源码依赖安装失败

如果 `npm ci` 报告 `@aio/models-data` 不存在，确认目录结构：

```text
parent/
├── AIO/
└── aio-models-data/
    └── dist/data/models.json
```

两个仓库必须处于同一父目录，且模型数据仓库包含构建后的 `dist/data/models.json`。

## Rust 或 Tauri 构建失败

- 使用 Rust stable 和 Node.js 20。
- 安装当前平台的 Tauri 2 prerequisites。
- Linux 安装 WebKitGTK、AppIndicator、Rsvg 和 patchelf。
- 先运行 `npm run build`，再在 `src-tauri` 运行 `cargo check`。
- 发布签名或 updater artifact 错误只影响正式发布构建，不影响普通开发运行。

仍无法解决时，在 [GitHub Issues](https://github.com/Atom112/AIO/issues) 提供系统版本、AIO 提交、复现步骤和脱敏后的错误日志。
